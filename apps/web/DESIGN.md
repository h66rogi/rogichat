# 로기챗 웹 디자인 기준

2026-09-20 · 첫 스타일: Airbnb-inspired · 적용 대상: 후로기 전용 웹 MVP.
이 문서는 구현 기준이며 웹 UI가 이미 만들어졌다는 의미는 아니다.
[구현 계획](../../docs/frontend-web-implementation-plan.md)과 함께 사용한다.
[다층 리뷰 기록](../../docs/frontend-web-implementation-review.md)에 지적과 반영 결과를 남긴다.

## 방향과 출처

후로기와 팬이 매일 방문하는 편안하고 명료한 채널 공간을 만든다. `/`에서 후로기의
사진·이름·소개와 채팅 진입이 바로 보이고, 채팅에서는 내용과 수신 대상이 우선한다.
멜로밍의 채널 프레임과 메뉴 구조에 아래 시각 기준을 적용한다.

사용자가 지정한 [shadcn.io Airbnb 디자인 자료](https://www.shadcn.io/design/airbnb)와
[원본 DESIGN.md](https://www.shadcn.io/design/airbnb/raw)의 색·여백·타이포그래피 원칙을
로기챗에 맞게 재정리했다. shadcn.io의 큐레이션 자료이며 공식 Airbnb 배포 키트나
공식 shadcn/ui 문서와 동일한 출처가 아니다. 원문 전체·로고·Cereal 폰트·사진은 복사하지 않는다.

밝은 바탕, 선명한 글자, 충분한 여백, 절제된 코랄 포인트를 사용한다. 실제 콘텐츠 사진을
주요 시각 요소로 삼되 승인된 자산이 없으면 중립 placeholder를 쓴다. 임의의 후로기 사진·소개·수치를 만들지 않는다.
숙박 검색창·여행 카테고리 같은 원본 서비스의 업무 UI를 가져오지 않는다.

## 초기 토큰

다음은 CSS semantic token으로 옮길 기준값이다. 색만으로 상태를 구별하지 않는다.

| 역할 | 값 | 적용 |
|---|---|---|
| canvas | `#ffffff` | 기본 배경 |
| surface-soft / strong | `#f7f7f7` / `#f2f2f2` | 섹션·hover·입력 보조 영역 |
| ink / body / muted | `#222222` / `#3f3f3f` / `#6a6a6a` | 제목·본문·보조 설명 |
| border / subtle | `#dddddd` / `#ebebeb` | 장식 경계·구분선. 입력 식별을 이 색만으로 처리하지 않음 |
| control-border / focus-ring | `#858585` / `#222222` | 흰 바탕 기준 3.69:1 / 15.91:1. 실제 surface·상태 조합은 별도 검사 |
| brand | `#ff385c` | 강조·선택 장식. 일반 크기 흰 글자의 배경으로 무조건 쓰지 않음 |
| action | `#e00b41` | 흰 글자 대비 4.89:1인 주 행동색. hover 등 실제 조합도 검사 |
| danger | `#c13515` | 삭제·실패. 아이콘/문구 동반 |
| radius | `4 / 8 / 14 / 20 / 32px`, pill `9999px` | 작은 요소 / 버튼·입력 / 카드·사진 / 큰 패널 등 |
| spacing | `2 / 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px` | 일관된 배치 간격 |

본문 16px/1.5, 보조 14px/약 1.43, 섹션 제목 22–28px를 기본으로 한다.
제목은 600–700, 본문은 400–500 범위로 사용한다. 거대한 홍보 문구를 채널 홈의 기본으로 삼지 않는다.
한국어는 초기 시스템 폰트(`system-ui`, `-apple-system`, `BlinkMacSystemFont`,
`Apple SD Gothic Neo`, `Malgun Gothic`, `sans-serif`)로 시작한다.
추가 웹폰트는 한글 가독성·라이선스·로딩 비용을 확인한 뒤 채택한다.

버튼 기본 높이 48px, 일반 입력 56px, 모바일 터치 영역 최소 44px를 기준으로 한다.
긴 채팅 입력은 여러 줄 확장을 지원한다. 카드/사진은 14px radius, 버튼/입력은 8px부터 시작한다.
얇은 경계를 기본으로 하고 그림자는 떠 있는 메뉴·dialog 등 계층 표현에 제한한다.
초기는 light 테마이며 다크 모드를 토큰 몇 개 반전한 상태로 제공하지 않는다.

## 레이아웃과 컴포넌트

| 영역 | 기준 |
|---|---|
| 채널 shell | 데스크톱 프로필/메뉴 + 본문, 모바일 축약 헤더/핵심 메뉴. 하나의 content tree 유지 |
| 홈 | 대표 이미지·프로필·소개·공식 링크 → 채팅 진입 → 확인된 보조 콘텐츠 |
| 메뉴 | 홈·채팅·이용 안내·내 설정부터. 제공할 데이터가 있는 기능만 활성화 |
| 채팅 | 타임라인 중심. 상단 문맥과 하단 입력창이 내용을 과도하게 가리지 않음 |
| 메시지 | 편한 줄 길이·시각·전송 상태·반응을 구분. 화려한 배경/그림자 반복 금지 |
| 입력창 | 팬은 인가된 스트리머에게 PRIVATE만, 스트리머는 SHARED/허용 팬 PRIVATE. 대상·인용 취소·전송 상태·재시도 |
| 설정 | 항목 라벨·설명·현재 상태를 가까이 배치. 생일 공개 범위는 설정 옆에서 설명 |
| dialog/sheet | 공개·삭제처럼 결과가 큰 동작에 대상과 결과를 짧게 설명 |

새 레이아웃을 완전히 발명하기 전에 `ChannelShell`·`ChannelLayout`·메뉴·talk 후보를 대조한다.
색·spacing·primitive는 이 기준에 맞추되 원본의 legacy CSS·브랜드·분석 SDK를 가져오지 않는다.
데스크톱/모바일 분기에서 채팅 트리를 이중 mount하지 않는다.

## 채팅의 시각적 의미

- 공통 메시지·개인답장·익명 공개본을 텍스트/아이콘으로 구분한다. 색상 차이에만 의존하지 않는다.
- 팬에게는 본인과 허용된 스트리머 정보만 보인다. 타 팬 목록·활동 수치를 꾸밈 요소로 넣지 않는다.
- PRIVATE 작성 중에는 수신 대상을 입력창 가까이에 지속 표시한다. 스와이프는 입력 상태만 바꾼다.
- 첫 메시지가 없는 팬에게도 서버가 제공한 수신자를 표시한다. 대상 없음/변경 시 입력 안내와
  송신 중지 상태를 제공하고 닉네임이나 사진으로 상대를 추정하지 않는다.
- 저장 완료와 읽음을 구별한다. 연결 중·복구 중·결과 확인 중·전송 거부를 구체적인 문구로 표시한다.
- 전체공개는 “해당 방 참여자에게 공개”라는 범위를 설명한다. 팬 승인 옵션을 임의로 추가하지 않는다.
- 긴 본문·인용·첨부 준비/실패·삭제 tombstone·반응 없는 메시지도 첫 화면안에 포함한다.

## 접근성과 상태

일반 텍스트 대비 4.5:1, 큰 글자와 의미 있는 UI 경계/아이콘은 적용 기준에 맞게 3:1 이상을 확인한다.
장식 border 두 색의 white 대비는 약 1.36:1/1.19:1이다. 입력·focus 식별에는 별도 control/focus
토큰을 쓰며 인접 색상과 검사한다. brand 코랄 위 흰색은 약 3.52:1이므로 일반 글자에는
action색 또는 검증한 전경색을 사용한다. 위 수치는 단색 조합 계산이며 실제 UI 검증을 대체하지 않는다.

모든 동작은 키보드와 스크린리더로 가능해야 한다. 명확한 focus ring, dialog focus 관리,
스와이프의 버튼 대안, 이미지 대체 텍스트, reduced motion을 제공한다.
한국어 IME 조합 중 Enter·모바일 키보드·safe area·텍스트 확대를 검증한다.
새 메시지 도착 시 읽던 위치나 focus를 빼앗지 않는다.

신규 메시지와 전송 실패·복구·PRIVATE 수신 대상 변경은 적절한 live/status 영역으로 알린다.
최초 로딩·history 추가·reset 재구축에서 타임라인 전체를 다시 낭독하지 않는다. 빠른 일괄 변경은
요약하고 입력 중 과도한 알림을 피한다. 실제 지원 스크린리더 조합에서 신규 수신·전송 실패·
개인답장 전환·history 추가·reset을 시험한다. 시각적 반응만으로 상태 전달을 완료하지 않는다.

미참여/퇴장 화면은 명시적 입장 버튼을 제공한다. 방 퇴장과 계정 탈퇴의 결과를 구별하고,
로그아웃 처리 결과가 불명확하거나 복귀 재인가 중이면 이전 계정 본문 없이 잠금/재시도 상태를 표시한다.

컴포넌트에는 기본·hover·focus·disabled·loading·empty·error·권한 부족 상태를 필요한 만큼 정의한다.
이미지가 없거나 API가 지연돼도 레이아웃이 무너지지 않게 크기와 대체 상태를 준비한다.
서버가 지원하지 않는 읽음·online·typing·통계는 fixture 장식으로 제품 화면에 남기지 않는다.

## 첫 화면 리뷰 기준

1. `/`이 여러 스트리머를 찾는 포털이 아니라 후로기의 공간으로 읽히는가.
2. 멜로밍 채널 구조의 재사용이 코드와 화면에서 확인되는가.
3. 팬/스트리머 모두 현재 메시지와 입력의 공개 범위를 혼동하지 않는가.
4. 작은 모바일 화면에서도 읽기·입력·메뉴 이동이 편하고 숨은 중복 mount가 없는가.
5. 로기챗 표기·자산·토큰·접근성·로딩/실패 상태가 일관되는가.

후속 스타일은 의미 토큰과 공통 UI 경계를 통해 확장한다. 첫 MVP에 테마 선택기나
다양한 스타일 preset을 미리 구현하지 않는다.
