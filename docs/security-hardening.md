# 공개 소스와 배포 산출물 보안

2026-09-20 보안 감사 후 보완한 개발 절차다. 개인 Git 이메일 공개는 소유자가
허용했다. 비밀정보·SSH 키·실제 인프라 입력은 공개 소스에 포함하지 않는다.

## QA 반영

1. 최신 QA에서 작업 브랜치를 만들고 자신의 변경만 커밋한다. 공유 디렉터리의
   다른 세션 작업은 보존한다. 별도 checkout을 사용해도 된다.
2. pinned scanner를 설치하고 hooks를 활성화한다. `tools/security/check.py staged`
   와 `all`을 통과한 뒤 브랜치를 게시하고 QA 대상 PR을 연다.
3. 현재 QA 기준의 `Public repository guard`, `verify`, `validate`,
   `Mobile required checks`가 모두 성공해야 반영한다. 다른 사람이 작성한
   승인 리뷰는 필수가 아니다. 새 QA 변경이 있으면 갱신하고 다시 검증한다.
4. QA push의 전체 검증 뒤 이미지 발행이 실행된다. 이미지 발행과 실제 클라우드
   배포·마이그레이션·Terraform apply는 별도의 승인 경로다.

모바일 workflow는 모든 PR에 최종 상태를 제공하지만 관련 파일이 바뀔 때만
Android/iOS 빌드를 실행한다. 삭제·이름 변경도 검사하며, 변경 범위를 확인할 수
없으면 실패한다. 문서만 바꿔도 모바일 필수 상태가 누락되어 PR이 잠기거나
불필요한 macOS 빌드 비용이 발생하는 것을 피한다. 수동 실행은 전체 빌드다.

GitHub의 action 허용 목록과 SHA 고정은 private ops에서 관리한다. Action을
업데이트할 때는 새 SHA와 출처를 검토하고 허용 목록을 먼저 갱신한 다음 소스를
변경한다. 스캐너·workflow·허용 목록 수정에는 독립적인 검토가 필요하다.

## 소스 검사

- 현재 index와 도달 가능한 Git 이력의 경로·내용·메타데이터를 검사한다.
  과거 파일을 삭제하는 것만으로 금지 자료가 허용되지는 않는다.
  전체 외부 PR refs는 별도 수동 `Public exposure audit`에서 가져와 검사한다.
  악성 외부 PR 하나로 모든 정상 작업을 막지 않도록 이 감사는 필수 QA gate와
  분리한다. 각 PR 자체의 검사는 계속 필수다.
- scanner 설정은 index와 작업 파일이 일치해야 하며 검토된 규칙만 허용한다.
  로컬 ignore 파일, 환경변수나 inline 주석으로 탐지를 억제하지 않는다.
- 공개키는 OpenSSH뿐 아니라 PEM/RFC4716 형식도 금지한다. 실제 state/plan은
  이름을 바꿔도 내용 구조를 검사한다. 템플릿과 정상 IaC 소스는 허용한다.
- 소스에 배포 패키지·임의 압축파일을 넣지 않는다. 기존 Gradle wrapper는 정확한
  경로와 검증한 공식 해시를 함께 확인한다. 다른 버전은 출처 검토와 정책 변경이
  필요하다. PNG 메타데이터·알 수 없는 바이너리도 조용히 건너뛰지 않는다.
- 검사 크기·개수 제한이나 오류가 발생하면 차단한다. 제한 변경은 실제 검사
  가능성을 검증한 뒤 조정하며, 특정 디렉터리 전체를 예외로 두지 않는다.
- 파일명 자체에 민감값이 있을 수 있으므로 오류에는 원문 경로를 출력하지 않는다.

큰 아카이브나 서명된 앱이 필요하면 Git 밖에서 빌드하고 해당 배포 경로를 이용한다.
이 정책은 정상 패키지 매니저 다운로드나 Git 밖의 QA 서명을 금지하지 않는다.

## 컨테이너 검사

발행 전에 runtime·migration 이미지의 모든 레이어와 config/history를 검사한다.
PR에서도 같은 검사를 백엔드 필수 상태에 포함해, 정상 의존성 업데이트의 검토가
필요한 경우 QA 반영 전에 알 수 있다. QA 발행에서는 실제로 발행할 이미지 ID를
다시 검사하고, push 직전 태그가 그 ID를 유지하는지 확인한다.
최종 파일시스템에서 삭제된 파일도 대상이다. 검사기는 컨테이너를 실행하지 않으며
archive 경로를 호스트 경로로 추출하지 않는다. 파싱 실패·제한 초과·스캐너 오류는
발행을 차단하고, 원문 후보나 상세 로그를 공개 artifact로 올리지 않는다.

공식 기반 이미지의 공개 테스트용 데이터도 자동으로 안전하다고 간주하지 않는다.
필요한 예외는 정확한 파일 해시·탐지 규칙·검증한 upstream 출처로 제한한다.
공개 파일명이 탐지된 경우에는 검사기가 생성한 파일명 메타데이터의 정확한 해시와
표현 형식을 별도로 명시한다. 파일 내용 전체를 면제하는 경로 규칙은 만들지 않는다.
파일 내용이 바뀌면 새 검토가 필요하다. 일반 `node_modules`나 기반 이미지 전체에
대한 제외 규칙은 없다. 이미 발행된 이미지의 export도 업로드 전에 같은 검사를 한다.

Docker build context는 환경 파일·서명 자료·Terraform 자료뿐 아니라 로컬 모바일
설정과 패키지 파일도 제외한다. `.gitignore`만으로 Docker context가 보호되지는 않는다.

## iOS 서명과 한계

전용 키체인의 비밀번호는 외부 0600 파일에서 읽어 macOS Security.framework에
메모리로 전달한다. 비밀번호가 든 subprocess 인자나 환경변수는 만들지 않는다.
기존 설정과 archive/export/upload 절차는 유지한다.
[서명 검증과 실패 처리](mobile-signing-security.md)를 참고한다.

로컬 hook과 CI는 공개된 모든 자료의 무해함을 수학적으로 보증하지 않는다.
공개 PR의 내용은 CI 전에 이미 공개되므로 게시 전 검사가 필요하다. 검토 권한을
가진 관리자가 검증 코드 자체를 악의적으로 바꾸는 위험, 임의 난독화와 이미지
스테가노그래피는 이 자동 검사의 보장 범위를 넘는다. GitHub 필수 CI도 Terraform
실행 권한이나 운영자 승인을 대신하지 않는다.
