# 팬 전용 채팅 전환 기준

2026-09-26 제품 기준. FAN 방에서 새 일반 메시지의 공개 범위는 작성자와 방장이다.
방장의 일반 메시지는 참여 팬에게 보이고, 방장이 팬 메시지를 선택해 보낸 답장은
해당 팬에게만 보인다. 방장이 팬 메시지를 별도로 전체공개할 때만 익명 공개본을
참여 팬에게 제공한다. 공개본은 작성자 이름·프로필·원본 ID를 전달하지 않는다.
본문이나 사진 자체에서 작성자를 추측할 가능성은 내부 개인정보 검토 항목으로 남긴다.

## 새 메시지 계약

| 동작 | 요청 | 저장·조회 범위 |
| --- | --- | --- |
| 팬 일반 메시지 | `ROOM_OWNER` | 작성 팬과 방장만. 방장이 아직 가입하지 않았으면 같은 비공개 범위로 보관 |
| 방장 일반 메시지 | `SHARED` | 참여 팬 |
| 방장의 선택 답장 | `PRIVATE` + 실제 팬 수신자와 인용 원본 | 방장과 선택된 팬 |
| 방장의 명시적 전체공개 | publication 명령 | 작성자 식별자를 제외한 별도 공개본을 참여 팬에게 제공 |

본문 조회, history/sync, 실시간 갱신 신호, 알림, 검색, 반응과 미디어 조회권은
모두 메시지의 현재 열람 권한을 기준으로 판정한다. 클라이언트 화면에서만 숨기는
방식은 공개 범위를 보장하지 않는다. 구형 클라이언트가 팬 역할로 `SHARED`를
보내더라도 새 팬 메시지가 다른 팬에게 퍼지지 않아야 한다.

## 이미 발송된 메시지

과거에 `SHARED`로 저장된 팬 메시지도 작성 팬과 방장에게만 조회된다. 저장된
원본 내용과 삭제 상태는 바꾸지 않고, 서버의 모든 열람 경로에서 작성자와 방장 관계를
확인해 다른 팬의 접근을 거부한다. 이미 다른 팬에게 표시되거나 알림·기기 캐시에
전달된 내용은 되돌릴 수 없으므로 재동기화와 캐시 무효화도 검증한다. 방장이
명시적으로 공개한 익명 사본은 별개의 공개 기록이다.

추가 제품 결정이 필요한 사항은 다음과 같다.

1. 이미 다른 팬에게 전달된 본문·첨부·알림·기기 캐시의 처리 기준.
2. 과거 공개본의 작성자 추론 가능성과 개별 삭제 요청의 처리 기준.
3. 기존 팬 메시지에 붙은 반응·인용 기록을 제한된 권한에 맞춰 처리할 범위.

기존 기록을 별도 스트림으로 임의 이전하거나 일괄 삭제하지 않는다. 개별 삭제
요청은 현재 제공하는 삭제·계정 권한 절차에 따른다.

## 확인 기준

서버를 먼저 갱신해 구형 클라이언트의 팬 발송을 안전하게 처리한 뒤 세 클라이언트를
갱신한다. QA에서 방장 1명과 팬 2명의 실제 계정으로 다음을 확인한다: 팬 A의 새
텍스트·사진·영상·스티커가 팬 B의 history/sync, 실시간 갱신, 검색, 알림, 반응,
미디어 URL에 나타나지 않는지; 방장에게는 보이는지; 방장의 일반 발송과 선택 답장이
각 대상에게만 보이는지; 명시적으로 전체공개한 사본에 작성자 식별자가 없는지.
기존 `SHARED` 기록은 변경하지 않았는지도 별도로 대조한다.
