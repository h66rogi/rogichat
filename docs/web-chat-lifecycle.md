# 웹 채팅 수명 주기 결정

2026-09-24. 범위: 웹 채팅의 라우트 복귀, 인증 확인, 실시간 힌트와 동기화.

## 결정

채팅의 영속 원본은 API와 DB다. 웹은 인증된 브라우저 세션에서 API를 직접 호출한다. Next 서버는 공개 화면 틀을 렌더링하고, 비공개 대화 내용은 브라우저가 현재 API 세션과 방 권한을 확인한 뒤 표시한다. 실시간 소켓과 웹 푸시는 변경 가능성을 알리는 힌트이며, 내용과 접근 권한은 동기화 API가 다시 판단한다.

채팅방 컴포넌트와 작성 중인 초안은 채널 메뉴 이동 동안 유지한다. 다른 메뉴에서는 채팅 소켓, 푸시 바인딩, 15초 주기 조회를 중지한다. 채팅으로 돌아오면 이전에 시작한 읽기나 전송이 끝난 뒤 새 권한 조회를 수행하고, 그 조회가 끝날 때까지 보관된 대화 DOM을 숨긴다. 권한 거부와 세션 변경 시에는 화면과 메모리를 비운다. 탭이 숨겨지거나 페이지를 떠나는 경우에는 기존의 비공개 화면 잠금과 언마운트를 유지한다.

겹친 포커스·복귀 이벤트는 진행 중인 세션 확인을 공유한다. 명시적인 로그아웃, 계정 변경, 권한 무효화는 그 확인을 취소하고 새로 검사한다. 채팅 동기화 중 추가 힌트가 오면 현재 조회가 끝난 뒤 한 번 더 읽는다. 연결 실패 이벤트 자체는 즉시 전체 조회를 반복하지 않고, 소켓 재연결과 활성 화면의 주기 조회에 맡긴다.

## SSR을 지금 채택하지 않은 이유

배포된 인증 쿠키는 API 호스트의 `__Host-` HttpOnly 쿠키다. 웹 호스트의 Next 요청에는 그 쿠키가 전달되지 않는다. 웹 서버에서 비공개 채팅을 SSR하려면 쿠키 범위를 넓히거나, 웹 호스트가 새로운 인증 세션을 소유하는 BFF로 인증·CSRF·로그아웃·OAuth 복귀·모바일 연동 경계를 재설계해야 한다. 화면 로딩 문제만을 위해 쿠키 보호 범위를 넓히지 않는다. 이번 문제의 직접 원인은 라우트 재마운트와 중복·누락된 재동기화였으므로, 기존 인증 경계에서 이를 해결한다.

브라우저의 전체 새로고침과 탭 복구에는 새 인증 및 데이터 조회가 필요하다. 이를 숨기기 위해 비공개 메시지를 영구 브라우저 캐시에 저장하지 않는다.

## 검증 기준

- 메뉴 이동 후 복귀 시 동일한 입력 DOM과 초안이 유지되고, 복귀 권한 조회 중에는 이전 대화가 보이지 않는다.
- 권한이 취소되면 이전 대화와 초안이 제거된다.
- 실행 중인 동기화에 새 힌트가 겹쳐도 후속 조회가 수행된다.
- 활성 채팅에만 소켓과 주기 조회가 붙고, 접근 실패에는 명시적인 오류·재시도를 표시한다.
- QA 배포 후 실제 이미지와 `/chat`, `/healthz`, API `/ready`를 확인한다.
