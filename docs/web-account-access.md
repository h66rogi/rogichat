# 웹 계정 로그인과 임시 관리 권한

실제 API 계정과 영속 권한을 사용한다. 운영자가 비공개 경로로 발급한 계정만
ID/PW 로그인에 사용할 수 있으며, 공개 가입·기본 비밀번호·클라이언트 역할 전환은 없다.

## 계약

- `POST /v1/auth/password/login`은 `clientId: web`, 입력한 `loginId`와
  `password`, 명시적으로 동의한 `termsVersion: 2026-09-20`을 전송한다.
  응답은 웹 Session이며 HttpOnly 쿠키를 통한 별도 session 조회가 같은
  partition/CSRF임을 확인한 뒤 기존 인증 게이트를 갱신한다.
- SOOP 연결 여부와 채팅 사용 권한은 다르다. 서버가 명시한
  `onboardingState: READY` + `capabilities.chat: true`는 SOOP `REQUIRED`와
  양립한다. 연결 상태는 그대로 표시하며 서버 권한이 없으면 채팅을 잠근다.
  이전 4필드 session 응답은 기존 VERIFIED 판정을 유지한다.
- 설정의 관리자 링크는 `GET /v1/me/capabilities`의 `admin.enabled`로 결정한다.
  `/admin`의 임시 권한 제어는 추가로 `manageTestAccess`가 필요하다.
  응답 오류는 권한으로 간주하지 않는다.
- 실제 기본방에 참여한 계정만 방 capabilities와 본인 grant 목록을 조회한다.
  미참여 시 기존 채팅방 참여 경로를 안내하며 자동 참여하지 않는다.
- `POST /v1/admin/rooms/:roomId/test-grants`는 본인에게만 5분·15분·1시간의
  권한을 요청한다. 같은 화면의 결과 불명확 요청은 원래 requestId와 본문을
  유지해 명시적으로 재확인한다. 서버가 반환한 목록과 역할을 조회하기 전에는
  성공으로 표시하지 않는다. 유효한 기존 grant가 있으면 새 발급을 막는다.
- 회수는 서버의 revoke endpoint를 사용한다. 발급·회수 뒤 기존 세션 게이트와
  채팅 scope를 갱신한다. 실제 권한·만료·감사는 서버가 결정하고, 웹은 영구 방장이나
  다른 계정으로 신원을 바꾸지 않는다.

## 생명주기 및 검증

비밀번호와 관리자 응답은 제품 저장소에 저장하거나 로그로 출력하지 않는다.
페이지 숨김·복귀 및 계정 변경은 기존 private-session 세대·취소 규칙을 사용한다.
mutation은 실제 CSRF와 현재 session binding을 확인한다. 서버 권한 회수 시
채팅의 메모리와 전송 권한도 폐기한다.

격리 테스트는 잘못된 비밀번호, 실제 응답 형식의 심사 계정 로그인·새로고침·채팅,
SOOP 미연결 표시, 일반 계정의 관리자 차단, 참여 전 발급 차단,
결과 불명확 발급의 동일 요청 재확인, 회수 및 pagehide/pageshow 권한 재확인을 다룬다.
합성 계정과 응답은 자동 테스트에만 존재한다.

이 변경은 관리자·비밀번호 API의 동시 준비가 필요하다. 계정 발급과 실제 배포 확인은
별도 운영 절차이며, UI 구현이나 격리 테스트 통과를 실제 서비스 사용 가능 판정으로
대체하지 않는다. 비밀번호 변경/계정 발급 UI는 이 화면의 제공 기능이 아니다.
