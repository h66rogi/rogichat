# 후로기 채널 원본 코드 이식 상태

이 브랜치는 일정·옷장·노래책의 Meloming 구현을 원본 파일 복사로 시작했다. 기준 커밋과 파일별 SHA-256은 `meloming-source-manifest.tsv`, 악보의 추가 QA 출처는 `meloming-qa-source-manifest.tsv`에 기록한다. 런타임에 남긴 프론트 복사본과 실제 마운트한 라우트의 변경 해시는 각각 `meloming-adaptations.tsv`, `meloming-mounted-route-adaptations.tsv`로 검증한다. 한 번 복사했지만 런타임에 연결되지 않는 프론트 파일과 백엔드 원본 스냅샷은 제거했다. 백엔드의 실제 실행 코드는 `apps/api/src/modules/channel-content`와 `upstream`에 있다.

멜로밍의 콘텐츠 레코드, 업로드 파일, 카탈로그 데이터는 이전하지 않는다. 기본 채널의 새 데이터는 로기챗 QA/운영 DB에서 독립적으로 생성된다.

## 현재 연결 범위

- 일정: 원본 캘린더·일정 관리·반복 일정·기념일·공지 화면 및 API. 일정에서 셋리스트 표시는 제외했다. 시간표 템플릿, 이미지 생성, SNS 설정은 라우트와 복사 코드에서 제거했다.
- 옷장: 원본 공개/상세/관리 UI, 분류와 항목 CRUD, 이미지 업로드 및 공개 읽기.
- 노래책: 원본 공개/관리/수동·엑셀 등록/CSV 다운로드/가수·분류 UI, 신청곡 설정, 라이브 세션·대기열·방송 기록·셋리스트 UI 및 실제 API. 원본 악보와 MR 영상 업로드, 가격·오마카세·앨범아트 검색·글로벌 곡 매칭 코드도 실행 경로에 있다. 공개 채널 메뉴 편집은 채널별 저장 API와 테이블에 연결했다.
- 인증·권한·업로드는 로기챗의 실제 계정, 단일 방, R2 저장소로 연결했다. 원본의 정수 채널/사용자 식별자는 공개 호환 별칭으로만 사용한다. 원본 멜로밍 로그인·콘솔·마케팅·분석 링크는 런타임에서 제거했다.
- 관리자 라이브 화면은 원본의 외부 콘솔 링크가 로기챗에서 동작하지 않아, 복사한 세션·신청곡 훅을 사용해 로컬 화면으로 묶었다.

## 아직 완료되지 않은 연결과 검증

- 노래책 모달의 클립 등록/재생/연결 UI와 캘린더 클립 카드는 원본 클립 API에 의존하지만 로기챗에는 아직 대응 모델·API가 없다. 이 부분은 끝나기 전까지 기능 동등성을 주장할 수 없다.
- 원본의 본인 인증, 채팅·후원 기반 신청, 오버레이 외부 콘솔, 사용자별 추천 계산 등은 현재 로기챗 계약과 차이가 있다. 해당 경로의 범위·실행 여부를 계속 조사해야 한다.
- 전체 웹 빌드와 API 계약 검사는 통과했다. 임시 MySQL 통합 검사에서 일정·옷장·노래책·라이브·악보·가격·메뉴 설정 저장을 검증했다. 실제 QA 웹 로그인, CRUD, 업로드, 공개 읽기, Socket.IO 및 배포된 이미지 digest 검증은 아직 필요하다.

이 문서는 중간 상태다. 위 미완료 항목을 정리하고 원격 검사·QA 배포를 확인한 뒤에만 완료로 표시한다.
